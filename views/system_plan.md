# レポート用システム設計書

## 共通の保存方法と操作

各システムのデータは JavaScript の配列とオブジェクトで管理し、それぞれ5人分の初期データを用意する。画面または REST API からメンバーを追加・変更・削除できる。データはメモリ内に保存され、サーバーの再起動時には初期状態に戻る。ID は各システム内で一意に採番する。未確認の項目は内部では null とし、画面と表では「未確認」と表示する。活動開始日・チャンネル URL、ミリプロの担当カラーは後から入力できる。

一覧画面には ID と名前を表示し、名前を選ぶと所属・期、活動開始日・デビュー日、チャンネル URL などを含む詳細画面へ移動する。一覧には名前による検索とメンバーの追加へのリンクを設ける。

## 1. ミリプロメンバー管理システム

### 対象

ミリプロに所属する配信者の基本プロフィール、活動開始日、YouTubeチャンネル、担当カラーを管理する。利用者は一覧からメンバーを選び、詳細情報を確認できる。

### ページ遷移

```text
トップページ
  └─ ミリプロメンバー一覧
       ├─ 追加 → メンバー登録画面 → 登録 → 一覧
       └─ メンバーを選択 → メンバー詳細画面
            ├─ 変更 → 編集画面 → 更新 → 詳細
            ├─ 削除 → 削除確認画面 → 削除 → 一覧
            │                         └─ キャンセル → 詳細
            └─ 一覧へ戻る
```

### スキーマ

| 項目名 | 型 | 内容 |
| --- | --- | --- |
| id | 整数 | メンバーを一意に識別するID |
| name | 文字列 | 活動名 |
| generation | 文字列 | 所属ユニット・期 |
| debut_date | 日付 | 活動開始日 |
| channel_url | 文字列 | YouTubeチャンネルのURL |
| color | 文字列 | 担当カラー |
